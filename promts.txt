# ==============================================================================
# HƯỚNG DẪN QUY CHUẨN DỰ ÁN VNCG & BỘ PROMPT MẪU CHO AI
# ==============================================================================

Dự án áp dụng kiến trúc **Vanilla HTML5 / CSS3 / JavaScript (ES6+)**, phát triển theo mô hình **Component-Driven**, quản lý giao diện tập trung qua **Design System (Tokens & Typography)** và điều khiển dữ liệu theo luồng **Props-Down (Không hardcode data)**.

---

## I. CẤU TRÚC THƯ MỤC CHUẨN (PROJECT ARCHITECTURE)

```text
VNCG/
│
├── assets/                          # Tài nguyên tĩnh
│   ├── Image/                       # Banner, logo công ty, ảnh nền, assets minh họa
│   └── fonts/                       # Phông chữ cục bộ (nếu có)
│
├── design-system/                   # Hệ thống thiết kế dùng chung (BẮT BUỘC TUÂN THỦ)
│   ├── tokens.css                   # Định nghĩa toàn bộ CSS Variables: Color, Spacing, Radius, Shadow
│   ├── typography.css               # Nạp Font (Inter/Google Fonts), Font-size, Font-weight, Line-height
│   ├── global.css                   # Reset CSS, CSS cơ bản cho Body/HTML, Container
│   └── icons.js                     # Thư viện SVG Icons chuẩn hóa toàn dự án
│
├── component/                       # Thư viện Component tái sử dụng (Component-driven)
│   ├── [ComponentName]/             # Tên folder component theo PascalCase
│   │   ├── [ComponentName].html     # Template khung HTML thuần
│   │   ├── [ComponentName].css      # Style riêng, 100% dùng CSS Variables từ tokens.css
│   │   └── [ComponentName].js       # Hàm render nhận props từ bên ngoài và render DOM
│   │
│   ├── ACGSCard/                    # Component thẻ thông tin chuẩn ACGS / Thẻ điều hướng
│   ├── Banner/                      # Component banner đầu trang
│   ├── CategoryProgress/            # Component thanh tiến độ theo nhóm tiêu chí
│   ├── CriteriaAccordion/           # Component danh sách tiêu chí dạng Accordion nhiều cấp
│   ├── SearchDetail/                # Component thanh tìm kiếm & bộ lọc tiêu chí
│   ├── SectionTitle/                # Component tiêu đề từng phân đoạn màn hình
│   └── StatCard/                    # Component thống kê số liệu (KPI/Cards)
│
├── layout/                          # Màn hình chức năng (Pages / Screens)
│   └── [Tên_Man_Hinh]/              # Tên màn hình theo snake_case hoặc PascalCase
│       ├── index.html               # Entry point màn hình (nạp DS, nạp components, khung layout)
│       ├── style.css                # CSS bố cục tổng (Grid layout, khoảng cách giữa các section)
│       └── script.js                # Controller: Lấy dữ liệu, tính toán KPI, truyền props render component
│
├── Mock_Data/                       # Dữ liệu giả lập mô phỏng API/Backend
│   └── DataACGS.js                  # Dữ liệu danh mục tiêu chí, kết quả đánh giá ACGS
│
└── promts.txt                       # Sổ tay quy chuẩn kiến trúc và bộ Prompt mẫu cho AI
```

## II. QUY TẮC BẮT BUỘC TUÂN THỦ (DESIGN SYSTEM & CODING RULES)

### 1. Không bao giờ hardcode dữ liệu trong HTML
- File `[ComponentName].html` chỉ đóng vai trò khung template hoặc thẻ chứa ID rỗng.
- Toàn bộ nội dung: tiêu đề, mô tả, con số, badge trạng thái, mảng dữ liệu **PHẢI** được truyền vào qua tham số `props` trong file `[ComponentName].js`.
- File `layout/[Tên_Man_Hinh]/script.js` chịu trách nhiệm tổng hợp dữ liệu từ `Mock_Data`, tính toán nghiệp vụ rồi truyền vào hàm render của component.

### 2. Tuân thủ triệt để Design System (CSS Tokens)
- **Màu sắc**: Không tự ý ghi mã màu hex tự do `#123456`. Phải dùng:
  - Màu thương hiệu: `var(--color-primary)`, `var(--color-primary-hover)`, `var(--color-primary-light)`...
  - Màu trạng thái: `var(--color-success)`, `var(--color-warning)`, `var(--color-danger)`, `var(--color-purple)`...
  - Màu trung tính & Text: `var(--color-text-title)`, `var(--color-text-body)`, `var(--color-border)`...
- **Khoảng cách**: Dùng `var(--spacing-xs)`, `var(--spacing-sm)`, `var(--spacing-md)`, `var(--spacing-lg)`, `var(--spacing-xl)`...
- **Bo góc**: Dùng `var(--radius-sm)`, `var(--radius-md)`, `var(--radius-lg)`, `var(--radius-full)`...
- **Bóng đổ**: Dùng `var(--shadow-sm)`, `var(--shadow-md)`, `var(--shadow-lg)`...
- **Phông chữ**: Dùng `var(--font-primary)`, các class tiện ích trong `typography.css`.

### 3. Chuẩn hóa SVG Icons
- Sử dụng hàm tiện ích `renderIcon(iconName, customClass)` hoặc lấy SVG từ `design-system/icons.js`.
- Không nhúng mã SVG thô trực tiếp lặp lại nhiều lần trong file HTML layout.

## III. BỘ PROMPT MẪU CHUẨN TƯƠNG TÁC VỚI AI (PROMPT TEMPLATES)

### 1. Prompt tạo Component mới từ ảnh thiết kế
```text
@[design-system/tokens.css] @[design-system/typography.css] @[design-system/icons.js]
Tạo component mới [TênComponent] trong thư mục @[component/[TênComponent]]:
1. [TênComponent].html: Khung HTML ngữ nghĩa, clean.
2. [TênComponent].css: Style chuẩn xác theo ảnh đính kèm, 100% sử dụng CSS variables từ design-system/tokens.css.
3. [TênComponent].js: Hàm render nhận `props` (title, value, status, icon, items...), không hardcode data.
Đính kèm ảnh UI: [Kéo thả ảnh vào khung chat]
```

### 2. Prompt chỉnh sửa Style theo Design / Ảnh chụp
```text
@[component/[TênComponent]/[TênComponent].css] @[component/[TênComponent]/[TênComponent].html]
Chỉnh sửa giao diện component [TênComponent] giống hệt trong ảnh:
- Khoảng cách, padding, font-size, màu sắc cần lấy từ design-system/tokens.css.
- Chỉnh [mô tả cụ thể: ví dụ thanh progress bar mảnh hơn, bo tròn, icon đổi màu].
Đính kèm ảnh UI: [Kéo thả ảnh vào khung chat]
```

### 3. Prompt tạo Layout màn hình mới ghép nối các Component
```text
@[design-system/tokens.css] @[design-system/typography.css] @[design-system/global.css]
Tạo màn hình mới tại @[layout/[Tên_Man_Hinh]]:
1. index.html: Nạp đúng thứ tự Design System -> Component CSS -> Component JS -> Mock Data -> script.js.
2. style.css: Bố cục lưới responsive (CSS Grid / Flexbox), khoảng cách các section đồng bộ.
3. script.js: Lấy dữ liệu từ @[Mock_Data/[TênData].js], map các trường và gọi hàm render của từng component tương ứng.
```

### 4. Prompt tích hợp / tính toán dữ liệu tự động (Dynamic Calculation)
```text
@[layout/[Tên_Man_Hinh]/script.js] @[Mock_Data/DataACGS.js]
Cập nhật logic trong script.js:
- Không hardcode các con số thống kê.
- Tự động duyệt qua mảng dữ liệu trong DataACGS để đếm số lượng tiêu chí cấp 2 (ví dụ: A.1, A.2...), tính tổng điểm, tỷ lệ hoàn thành.
- Truyền kết quả đã tính vào các component StatCard và CategoryProgress.
```

### 5. Prompt kiểm tra và làm sạch dự án (Clean-up & Compliance Audit)
```text
@[component] @[layout] @[design-system]
Kiểm tra toàn bộ code trong component và layout:
- Rà soát các mã màu hex hoặc kích thước còn bị hardcode chưa chuyển sang CSS variable của design-system/tokens.css.
- Xóa các import font thừa hoặc thẻ style inline trong file HTML.
- Đảm bảo component nhận đầy đủ dữ liệu qua props từ script.js.
```

## IV. VÍ DỤ CÁC PROMPT THỰC TẾ TRONG DỰ ÁN

### Ví dụ 1: Tạo thẻ thống kê StatCard
```text
@[component/StatCard] @[design-system/tokens.css]
Tạo component StatCard hỗ trợ nhận các props động:
- title: Tiêu đề thẻ (ví dụ: "Tổng điểm thực hiện")
- value: Giá trị chính (ví dụ: "85.5")
- suffix: Đơn vị phía sau (ví dụ: "/100" hoặc "%")
- subValue: Dòng mô tả nhỏ bên dưới
- progress: Phần trăm tiến độ (0 - 100)
- iconType: Tên icon lấy từ icons.js
- theme: Màu chủ đạo ('primary' | 'success' | 'warning' | 'purple')
```

### Ví dụ 2: Tạo Accordion danh sách tiêu chí
```text
@[component/CriteriaAccordion] @[design-system/tokens.css] @[Mock_Data/DataACGS.js]
Tạo component CriteriaAccordion dạng cây phân cấp (Cấp 1: A/B/C/D/E -> Cấp 2: A.1, A.2... -> Cấp 3: Tiêu chí chi tiết).
Nhận props: danh sách categories, callback khi click xem chi tiết hoặc thay đổi trạng thái lọc.
```

### Ví dụ 3: Ghép trang Thực hiện ACGS
```text
@[layout/Thuc_hien_ACGS/index.html] @[layout/Thuc_hien_ACGS/script.js] @[layout/Thuc_hien_ACGS/style.css]
Rà soát và hoàn thiện trang Thực hiện ACGS:
- Ghép nối Banner, ACGSCard, SectionTitle, StatCard, CategoryProgress, SearchDetail, CriteriaAccordion.
- Đảm bảo script.js tính toán chuẩn xác tỷ lệ câu hỏi Tuân thủ / Chưa tuân thủ và điểm số từng nhóm A, B, C, D, E từ Mock_Data.
